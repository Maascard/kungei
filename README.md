# Kungei — сайт аренды коттеджа

Современный двуязычный (русский / казахский) сайт коттеджа **Kungei** с галереей,
меню, информацией, отзывами, картой и полноценной системой онлайн-бронирования с
календарём, базой данных и админ-панелью.

- **Стек:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Prisma
- **БД:** SQLite (локально) / PostgreSQL (продакшен на Vercel)
- **Заявки** автоматически отправляются клиентом в **WhatsApp** (с готовым текстом)
  или **Instagram** (открывается чат) — и при этом **сохраняются в базе** и видны в админке.

## 1. Быстрый запуск локально (Windows)

```powershell
# 1. Установить зависимости
npm install

# 2. Создать файл .env (скопировать из примера) — он уже создан с локальными настройками
#    Если его нет:  Copy-Item .env.example .env

# 3. Создать базу данных (SQLite) и заполнить демо-контентом
npm run db:push
npm run db:seed

# 4. Запустить сайт
npm run dev
```

Открыть: **http://localhost:3000** (автоматически перенаправит на `/ru`).

Админка: **http://localhost:3000/admin**
- логин: `admin`
- пароль: `kungei2026` (задан в `.env`, обязательно смените)

> Для локального просмотра используйте `npm run dev`. Команда `npm start`
> (production-режим) помечает cookie входа как `Secure`, и админка работает только
> по HTTPS — то есть на боевом домене, а не на `http://localhost`.

## 3. Как менять контент (без программиста)

Войдите в **/admin** — там 6 вкладок:

- **Заявки** — все брони из базы. Кнопки «Подтвердить» / «Отменить» / «Удалить».
  Заявки в статусе «Ожидает» и «Подтверждено» **блокируют даты** в календаре.
- **Календарь / блокировки** — вручную закрыть даты (ремонт, личное использование).
- **Галерея** — добавить/удалить фото, подписи на двух языках.
- **Меню** — категории и блюда (название, описание, цена, фото, на двух языках).
- **Отзывы** — добавить/удалить отзывы гостей.
- **Настройки** — контакты (WhatsApp, Instagram), адрес, координаты карты,
  тексты первого экрана, описание, удобства, условия аренды и т.д. — всё на ru/kk.

> ⚠️ **Важно настроить в «Настройках» перед запуском:**
> - **WhatsApp** — номер только цифрами в международном формате, напр. `77001234567`.
> - **Instagram** — логин без `@` (`kungei_45`).
> - **Координаты карты** (широта/долгота) — взять из Google Maps / 2GIS.

### Загрузка фото
Загрузка файлов работает через **Vercel Blob** (нужен `BLOB_READ_WRITE_TOKEN`).
Без токена просто **вставляйте ссылку на фото (URL)** — это поддерживается везде.

## 4. Деплой на Vercel + PostgreSQL

1. **Создайте базу Postgres** (бесплатно): [Neon](https://neon.tech) или
   Vercel → Storage → Postgres. Скопируйте строку подключения.

2. **Переключите Prisma на Postgres** — в `prisma/schema.prisma`:
   ```prisma
   datasource db {
     provider = "postgresql"   // было "sqlite"
     url      = env("DATABASE_URL")
   }
   ```

3. **Залейте проект на GitHub** и импортируйте в Vercel.

4. **Задайте переменные окружения** в Vercel (Settings → Environment Variables):
   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения Postgres |
   | `ADMIN_USERNAME` | ваш логин админа |
   | `ADMIN_PASSWORD` | надёжный пароль |
   | `AUTH_SECRET` | длинная случайная строка (≥32 символов) |
   | `BLOB_READ_WRITE_TOKEN` | токен Vercel Blob (для загрузки фото; опционально) |

5. **Примените схему и заполните данные** (один раз). Локально, указав в `.env`
   тот же `DATABASE_URL` от Postgres:
   ```powershell
   npm run db:push
   npm run db:seed
   ```
   (либо через Vercel CLI / любой клиент, выполнив `prisma db push`).

6. Vercel соберёт проект (`npm run build` уже включает `prisma generate`).

Готово. Сайт будет доступен по адресу Vercel, админка — на `/admin`.

## 5. Как работает защита от двойного бронирования

- Каждая заявка хранит диапазон дат и статус (`pending` / `confirmed` / `cancelled`).
- Занятыми считаются все дни диапазонов со статусом `pending` или `confirmed`,
  плюс ручные блокировки админа.
- Создание заявки выполняется в транзакции с уровнем изоляции **Serializable** и
  повторной проверкой пересечения дат — две одновременные заявки на одну дату
  не пройдут (вторая получит ошибку «даты заняты»).
- Календарь на сайте подгружает занятые даты и показывает их **зачёркнутыми/недоступными**.

## 6. Чат-бот WhatsApp с ИИ (Claude)

Бот автоматически отвечает клиентам в WhatsApp на русском и казахском, рассказывает о
коттедже (берёт инфо, меню и **занятые даты** из базы) и отправляет ссылку на сайт для
бронирования. Вся переписка сохраняется в базе.

**Как это работает:** клиент пишет в WhatsApp → Meta присылает сообщение на webhook
`/api/whatsapp/webhook` → Claude формирует ответ → ответ уходит обратно в WhatsApp.

### Что нужно настроить

1. **Ключ Anthropic** — зарегистрируйтесь на [console.anthropic.com](https://console.anthropic.com),
   создайте API-ключ, положите в `ANTHROPIC_API_KEY`. (Модель по умолчанию — `claude-opus-4-8`;
   для экономии можно поставить `CHATBOT_MODEL=claude-haiku-4-5`.)

2. **WhatsApp Cloud API** на [developers.facebook.com](https://developers.facebook.com):
   - Создайте приложение → добавьте продукт **WhatsApp**.
   - Скопируйте **Phone Number ID** → `WHATSAPP_PHONE_NUMBER_ID` и **Access Token**
     → `WHATSAPP_ACCESS_TOKEN` (для постоянной работы нужен permanent token).
   - В **App Settings → Basic** скопируйте **App Secret** → `WHATSAPP_APP_SECRET`.
   - Придумайте любую строку для `WHATSAPP_VERIFY_TOKEN`.

3. **Подключите webhook** (в разделе WhatsApp → Configuration):
   - Callback URL: `https://ваш-домен/api/whatsapp/webhook`
   - Verify token: то же значение, что в `WHATSAPP_VERIFY_TOKEN`
   - Подпишитесь на поле **messages**.

4. Укажите `SITE_URL` — публичный адрес сайта (бот шлёт эту ссылку клиентам).

> ⚠️ Webhook требует **публичный HTTPS-адрес** — то есть рабочий деплой на Vercel.
> Для локальной отладки используйте туннель (например `ngrok http 3000`) и временно
> укажите его адрес как Callback URL в Meta.

Все переменные — в `.env` (локально) и в переменных окружения Vercel (на проде).
Если ключи не заданы, сайт и бронирование работают как обычно, просто бот не отвечает.

## Полезные команды

```powershell
npm run dev        # запуск в режиме разработки
npm run build      # production-сборка
npm run start      # запуск production-сборки (только по HTTPS для админки)
npm run db:push    # применить схему к БД
npm run db:seed    # заполнить демо-контентом
npm run db:studio  # визуальный просмотр базы (Prisma Studio)
```
